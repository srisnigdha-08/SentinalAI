**Document Version:** 1.0.0

## 1. Executive Summary and Scope
This contract establishes the definitive, quantitative, and binding acceptance criteria for closing SentinelAI GATE-1. GATE-1 governs the validation and promotion readiness of the machine learning threat detection engine, modular detector pipeline, and host safety controls.

Prior to closing GATE-1, the system must empirically satisfy all criteria specified herein across independent holdout evaluation datasets, without label leakage, synthetic evaluation fabrication, or host safety compromises.

---

## 2. Quantitative Gate Thresholds

### 2.1 Benign False Positive Rate (FPR)
To prevent operational alert fatigue and accidental denial-of-service against legitimate traffic:
- **Sample Size Requirement:** Evaluated on an independent, holdout benign traffic sample of $N \ge 30,000$ flows.
- **Point Estimate:** $\text{FPR} = \frac{\text{FP}}{\text{FP} + \text{TN}} < 0.10\%$ (fewer than 1 false positive per 1,000 legitimate flows).
- **Statistical Upper Bound:** 95% Wilson Score Interval upper bound:
  $$\text{Wilson}_{95\%}(\text{FPR}) < 0.10\%$$
  *(Note: For $N = 30,000$, achieving an upper bound $<0.10\%$ requires an observed point estimate of $\le 0.067\%$, or $\le 20$ false positives).*

Evaluated on independent, held-out attack traffic partitions unseen during any training or hyperparameter tuning:
| Attack Family | Specific Attack Types / Tools | Minimum Recall Target | Baseline Reported (Phase 7/8/9A) |
|---|---|---|---|
| **PortScan** | Nmap SYN/FIN/Null scans, Netflow port sweeps | **$\ge 90.0\%$** | 99.98% (Phase 8 Multi-corpus) |
| **SSH Brute Force** | Hydra, Medusa, SSH auth flood | **$\ge 80.0\%$** | 50.90% (Phase 8 Multi-corpus) |
| **FTP Brute Force** | Hydra, Patator, anonymous abuse | **$\ge 80.0\%$** | 99.41% (Phase 8 Multi-corpus) |
| **DoS / DDoS** | LOIC, HOIC, Slowloris, SYN Flood | **$\ge 80.0\%$** | 0.00% (HOIC CSE-2018 in Phase 7/8/9A) |

| **Web Attacks** | SQL Injection (SQLi), Cross-Site Scripting (XSS), Brute Force | **$\ge 80.0\%$** | 0.35% (Transport features) / Simulated 100% (Audit Finding C-07) |

### 2.3 Operational Latency and Throughput
- **Single Request p95 Latency:** $\le 100\text{ ms}$ wall-clock execution time across the complete modular pipeline under single-thread execution.
- **Worker Saturation Latency:** If worker pool queue or in-flight limit reaches capacity ($C = 16$), the orchestrator must fast-fail within $\le 5\text{ ms}$ returning fail-safe `MONITOR`.

## 3. Failure-Safety and Host Containment Semantics

### 3.1 Strict Fail-Safe Invariant
Under any failure condition—including unhandled detector exceptions, pipeline timeouts, worker pool exhaustion, corrupted flow telemetry, or non-finite inputs ($NaN$, $\pm\infty$):
1. Overall pipeline decision **MUST** fail safe to `MONITOR`.
2. Pipeline status **MUST** be recorded as `UNAVAILABLE` or `ERROR`.
3. An action of `BLOCK` or `TERMINATE_PROCESS` is **STRICTLY PROHIBITED** on failure.

### 3.2 Distinction of Operational States
| Term | Formal Definition | Authorized in GATE-1? |
|---|---|---|
| **Detection** | Classification or anomaly score generated by an ML model or heuristic module. | YES (Shadow mode) |
| **Alerting** | Logging of detected threat event to internal memory, audit files, or backend UI. | YES (Shadow mode) |
| **Simulated Block** | Recommendation of `BLOCK` with `simulated = True` recorded in pipeline response. | YES (Shadow mode) |
| **Real Enforcement** | Executing `netsh advfirewall` or modifying host firewall rules to drop traffic. | **STRICTLY PROHIBITED** |

### 3.3 Safety Flag Invariants
- `AUTONOMOUS_CONTAINMENT = False` (Mandatory)
- `ENABLE_REAL_WINDOWS_FIREWALL_ENFORCEMENT = False` (Mandatory)
- `ENABLE_EXPERIMENTAL_MODULAR_DETECTORS = False` in production inference paths until Gate 1 closure.
- Active host firewall `SentinelAI*` netsh rules must strictly equal **0**.

## 4. Prohibited Evaluative Practices
1. **Ground-Truth Label Leakage:** Detectors, parsers, and extractors must operate strictly on protocol headers, payload content, and netflow metrics. Any reference to ground-truth label columns (e.g. `Label`, `Attack`, `is_malicious`) inside detection logic is strictly prohibited and constitutes automatic audit failure.
2. **Synthetic / Fabricated Metrics:** All evaluation numbers must be directly computed from actual model execution on verified disk-backed dataset partitions. Simulating or inventing confusion matrices is strictly prohibited.
3. **Holdout Contamination:** No sample appearing in the evaluation holdout sets may have been present in candidate training or hyperparameter tuning partitions.
