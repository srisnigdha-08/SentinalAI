## 1. Architectural Scope & Core Principles

The SentinelAI detection and containment pipeline connects a Python-based machine-learning inference engine with a Node.js backend. In previous releases, the contract between these two subsystems was loose:
1. Python yielded raw scores and proposed actions.
2. The Node.js backend recalculated actions from raw numerical scores using disconnected threshold logic.
3. Network failures, model crashes, and timeouts collapsed into `null`, causing the ingestion pipeline to fail open silently.
4. Schema enums in MongoDB models (`ThreatLog`, `Alert`) lacked status codes for degraded and uninspected states.

This specification establishes an explicit, fail-safe **Failure-State Contract** governing all inference outcomes across the system.

### Invariant Security Axioms:
1. **Never Fail Open to Benign:** An inference failure, service outage, timeout, or degraded prediction must **never** be classified as `BENIGN` or granted an ordinary, unmonitored `ALLOW`.
2. **Explicit Action Ownership:** The Python safety policy owns policy candidate classification and suggested containment action. The Node.js backend validates payload integrity and enforces containment policy invariants (such as IP safety whitelists, rate limits, and operator autoBlock toggles). The backend must never unilaterally overwrite a safety-mandated `MONITOR` with `ALLOW`.
3. **Simulated vs. Real Enforcement:** As long as `AUTONOMOUS_CONTAINMENT=false` and `ENABLE_REAL_WINDOWS_FIREWALL_ENFORCEMENT=false`, any `BLOCK` action generated by policy remains strictly a **simulated policy decision**. It is tracked in telemetry as `simulated_block` or held at `MONITORING`, with zero packet drop commands dispatched to the OS firewall.
4. **Observable Audit Fallback:** If primary database persistence fails, an emergency structured log line must be written to an immutable local fallback file so security audits cannot be silenced.

## 2. Formal Inference State Taxonomy

The SentinelAI ingestion pipeline recognizes 6 distinct operational states:

```
+--------------------------------------------------------------------------------------------------+
|                                    INFERENCE STATE TAXONOMY                                      |
+-----------------------------------+--------------------------------------------------------------+
| 1. HEALTHY_SUCCESS                | Model inference succeeded with high confidence.             |
| 2. DEGRADED_UNCERTAIN             | Model inference succeeded but flags high uncertainty or OOD. |
| 3. SERVICE_UNAVAILABLE            | HTTP timeout, ECONNREFUSED, or HTTP 500/502/503 from engine. |
| 4. INVALID_RESPONSE               | Payload malformed, missing fields, or schema invalid.        |
| 5. PERSISTENCE_FAILURE            | Database write to AIPrediction or ThreatLog rejected/down.  |
| 6. NOTIFICATION_FAILURE           | WebSocket or Alert generation failed after persistence.      |
+-----------------------------------+--------------------------------------------------------------+
```

## 4. Contract Rules & Invariant Enforcements

### 4.1 Action Ownership & Precedence Rule
To prevent the Node.js backend from overriding safety-mandated actions:
1. If `inferenceResult.status === 'DEGRADED'` or `inferenceResult.predictedClass === 'UNINSPECTED_TRAFFIC'`, the action **must strictly be `MONITOR`**.
2. If `inferenceResult.action` is provided by the Python candidate policy and is `'MONITOR'`, the backend **must honor `MONITOR`** even if `threatScore < 0.70`.
3. If `inferenceResult.action === 'BLOCK'`, the backend verifies whether `autoBlockEnabled === true`. If `false`, the threat status is set to `MONITORING`, and the public response reports `action: 'BLOCK'`, `simulated: true`.

```
                    +-----------------------------+
                    |  Inference Payload Received |
                    +--------------+--------------+
                                   |
                     Is Status DEGRADED/UNAVAILABLE?
                                  / \
                                 /   \
                               YES   NO
                               /       \
              +---------------+         +--------------------------+
              | Force Action: |         | Is result.action set?    |
              |    MONITOR    |         +------------+-------------+
              +---------------+                     / \
                                                   /   \
                                                 YES   NO
                                                 /       \
                              +-----------------+         +------------------------+
                              | Honor provided  |         | Fallback to threshold: |
                              | result.action   |         | S >= block ? BLOCK     |
                              +-----------------+         | S >= 0.70  ? MONITOR   |
                                                          | Else       ? ALLOW     |
                                                          +------------------------+
```

### 4.2 Durable Audit Logging Fallback (Emergency Disk Logging)
When MongoDB persistence fails:
1. The backend must not claim durable database auditing.
2. The service dispatches an emergency JSON audit record to `logs/emergency_audit.log` via Winston file transport:
   ```json
   {
     "timestamp": "2026-10-16T13:45:00.000Z",
     "event": "PERSISTENCE_FAILURE_EMERGENCY_AUDIT",
     "sourceIP": "192.168.1.105",
     "threatScore": 0.50,
     "assignedAction": "MONITOR",
     "status": "DEGRADED",
     "error": "MongoNetworkError: connection timed out"
   }
   ```
3. This guarantees non-repudiation and external observability even during complete database cluster failure.

## 5. Schema Alignment Requirements

To support this contract without runtime `ValidationError` exceptions, the following schema expansions are formally required:

### 1. `backend/models/ThreatLog.js`
* Expand `status` enum:
  ```javascript
  status: {
    type: String,
    enum: [
      'DETECTED',
      'MONITORING',
      'BLOCKED',
      'ESCALATED',
      'RESOLVED',
      'FALSE_POSITIVE',
      'DEGRADED'        // <--- Required addition
    ],
    default: 'DETECTED',
    index: true,
  }
  ```
* Expand `attackType` enum:
  ```javascript
  attackType: {
    type: String,
    required: true,
    enum: [
      'SSH Brute Force',
      'SSH Intrusion Attempt',
      'SQL Injection',
      'Port Scan',
      'DDoS',
      'RCE Attempt',
      'XSS Attempt',
      'Malware Beacon',
      'Credential Stuffing',
      'Ransomware',
      'Lateral Movement',
      'Data Exfiltration',
      'Zero-Day Exploit',
      'Unknown',
      'UNINSPECTED_TRAFFIC' // <--- Required addition
    ],
  }
  ```

### 2. `backend/models/Alert.js`
* Expand `sourceRef.refModel` enum:
  ```javascript
  sourceRef: {
    refModel: {
      type: String,
      enum: ['ThreatLog', 'HoneypotSession', 'User', 'AIPrediction'] // <--- Added AIPrediction
    },
    refId: { type: mongoose.Schema.Types.ObjectId },
  }
  ```

### 3. `backend/models/AIPrediction.js`
* Add `status` and `action` tracking fields:
  ```javascript
  status: {
    type: String,
    enum: ['HEALTHY', 'DEGRADED', 'UNAVAILABLE', 'INVALID_RESPONSE'],
    default: 'HEALTHY',
    index: true
  },
  policyAction: {
    type: String,
    enum: ['ALLOW', 'MONITOR', 'BLOCK'],
    default: 'ALLOW',
    index: true
  }
  ```
