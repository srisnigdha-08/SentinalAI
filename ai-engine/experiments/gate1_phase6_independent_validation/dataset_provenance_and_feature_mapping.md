## 1. Provenance and Environmental Context of CSE-CIC-IDS2018

The **CSE-CIC-IDS2018** dataset was created by the Canadian Institute for Cybersecurity (CIC) at the University of New Brunswick (UNB) in partnership with the Communications Security Establishment (CSE), Canada's national cryptologic agency.

### Environmental Topology:
- **Cloud Infrastructure**: Deployed on Amazon Web Services (AWS) using 400 victim EC2 instances distributed across 36 distinct subnets (victim departments), and 50 attacking EC2 instances.
- **Capture Timeline**: Spanned 10 full operational business days from **February 14, 2018 through March 2, 2018**.
- **Network Traffic Profiles**: Includes naturalistic human background traffic (HTTP, HTTPS, SSH, FTP, Email, DNS) generated by automated agent profiles alongside targeted attack executions.
- **Physical Independence**: Completely distinct physical topology, IP addressing, date, and cloud environment from CICIDS2017. Models trained on CICIDS2017 have **0% sample overlap** with CSE-CIC-IDS2018.

## 4. Methodological Independence vs. Residual Leakage

While CSE-CIC-IDS2018 solves the **data memorization** blocker by providing 100% unseen flow records, the auditor must document two residual methodological correlations:
1. **Tooling Invariance**: Both datasets were extracted using the University of New Brunswick's `CICFlowMeter` Java application. Any bugs or systematic biases in flow duration timeouts (e.g., 120-second TCP flow cutoffs) or subflow packet aggregation are shared between the datasets.
2. **Attack Script Artifacts**: Several attack tools used in 2018 (LOIC for DDoS, Ares for Botnet, Patator for SSH) were parameterized similarly to 2017. While this represents a valid test of attack signature transfer, it does not evaluate zero-day evasion techniques.

**Conclusion**: CSE-CIC-IDS2018 provides a rigorous, genuine out-of-distribution benchmark that eliminates the training set overlap fatal to 2017 minority evaluations.
