## 3. Track B: Authorized Enterprise Canary Traffic

### 3.1. Operational and Legal Governance Framework
Capturing and evaluating enterprise canary network traffic introduces significant regulatory and privacy constraints:
1. **Consent and Authorization**:
   - Traffic monitoring must comply with enterprise Acceptable Use Policies (AUP), GDPR Article 6(1)(f) (Legitimate Interest for Network Security), and local wiretap / privacy legislation.
   - Explicit written authorization from the Chief Information Security Officer (CISO) and Legal Counsel is required prior to deploying passive network taps.
2. **Privacy Redaction and Data Minimization**:
   - Transport-layer flow statistics (IP addresses, ports, byte counts, TCP timings) contain no direct user payloads.
   - However, Layer 7 HTTP inspection requires strict runtime scrubbing:
     * Request headers `Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization` must be stripped or hashed before logging.
     * Request bodies containing JSON fields `password`, `token`, `secret`, `ssn`, `credit_card` must be redacted via regex tokenizers prior to telemetry persistence.
3. **Controlled Attack Injection**:
   - Penetration testing tools (sqlmap, OWASP ZAP, hydra, nmap) must target strictly isolated, dedicated sandbox servers (canary endpoints) residing on an air-gapped VLAN.
   - Injection traffic must carry a cryptographically signed HTTP header:
     `X-Sentinel-Canary-Run: <UUID>.<HMAC-SHA256>`
     This provides microsecond-precise ground-truth labeling without manual annotation errors.

### 3.2. Traffic Visibility and TLS Inspection Architecture
Modern web traffic is $>95\%$ TLS 1.3 encrypted. In order to perform Layer 7 inspection:
1. **Option 1 (Recommended — Reverse Proxy Termination)**: Deploy the Layer 7 WAF pre-filter inside an API gateway or reverse proxy (e.g., Envoy, NGINX, Cloudflare Worker) where TLS is terminated prior to upstream routing.
2. **Option 2 (eBPF Socket Probing)**: In Linux environments, attach eBPF `uprobes` to OpenSSL/BoringSSL (`SSL_read`, `SSL_write`) to inspect cleartext buffers immediately before/after encryption without breaking TLS cert chains.
3. **Option 3 (Out-of-Band Mirroring with SSLKEYLOGFILE)**: For passive network taps, capture ephemeral session keys via `SSLKEYLOGFILE` into an isolated, memory-only key cache. (High operational complexity and key-management security risk).
