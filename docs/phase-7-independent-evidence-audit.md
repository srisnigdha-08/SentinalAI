## 2. Priority 1 — AI Evaluation Correctness and Detection Quality

### 2.1 Empirical Diagnosis of the 100% False-Negative Rate on Synthetic Data

Previous verification reports observed a 100% false-negative rate (zero attack detections) when running `evaluate_model.py` against synthetic validation data generated by `utils/data_generator.py`. The independent audit investigated this behavior across four potential failure modes:

1. **Model Degradation / Artifact Corruption**: **DISPROVEN**.
   - Inspection of `ai-engine/models/rf_classifier_cicids_v2.pkl` (SHA-256: `CA0EFB1FDE8F9BDC430C3C511E32CD91822B0F3DEECA845AA259BC8DD60023F1`) demonstrated that the model was trained on real CICIDS2017 network flows with 53 features and `StandardScaler` normalization.
   - When evaluated against 1,000 held-out samples from the official CICIDS2017 Friday PortScan dataset (`Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv`), the model achieved **99.0% recall** and **100% precision** on PortScan attacks.
   - When evaluated against 1,000 held-out samples from the CICIDS2017 Friday DDoS dataset (`Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv`), the model achieved **99.8% recall** and **99.8% precision** on DDoS attacks.

2. **Synthetic Data Feature Incompleteness**: **CONFIRMED**.
   - `utils/data_generator.py` only generated 43 features, omitting 7 crucial TCP window and flow activity features:
     - `init_win_bytes_forward`
     - `init_win_bytes_backward`
     - `active_mean`
     - `active_std`
     - `idle_mean`
     - `idle_std`
     - `down_up_ratio`
   - In addition, the synthetic ranges for packet sizes and durations fell within ambient baseline norms rather than the severe distributions characteristic of network attacks.

3. **Feature Extraction Alignment & Header Whitespace Defect**: **CONFIRMED & FIXED**.
   - In `utils/features.py`, `extract_features_from_record(record)` previously performed direct dictionary lookups: `record.get(feat, default)`.
   - The official CICIDS2017 CSV headers contain leading whitespace (e.g. ` Destination Port`, ` Flow Duration`, ` Total Fwd Packets`).
   - Consequently, when raw CSV rows or dictionaries were passed to `extract_features_from_record`, all candidate names failed to match, collapsing the feature vector to default fallbacks (`0.0` or `60.0`), which the Random Forest invariably classified as class 0 (`BENIGN`).
   - In addition, division-by-zero in raw PCAP flow records created `inf` and `-inf` values in `Flow Bytes/s`, which caused unhandled `ValueError: Input X contains infinity` exceptions in Scikit-learn pipelines.

### 2.2 Fixes Implemented in Feature Extraction & Evaluation

1. **Whitespace-Tolerant Feature Extraction (`ai-engine/utils/features.py`)**:
   - `extract_features_from_record` was updated to build a normalized lookup dictionary matching keys regardless of leading/trailing whitespace, casing, underscores, or slashes.
   - Added automatic sanitization of `inf`, `-inf`, and `nan` values to finite floats (`0.0`).
2. **Pure, Guarded Classification Metric Calculation (`ai-engine/evaluation/evaluate_model.py`)**:
   - Implemented `compute_classification_metrics(y_true, y_pred, all_classes=None)`:
     - Zero-division guards for FPR (`FP / (FP + TN)`), FNR (`FN / (FN + TP)`), precision, recall, and F1.
     - Handles empty inputs gracefully (returns sampleCount: 0 and 0.0 metrics without throwing).
     - Computes binary Benign vs Malicious confusion matrices alongside multiclass macro and weighted metrics.
3. **Real CICIDS Evaluation Pipeline (`evaluate_cicids_held_out`)**:
   - Added automated evaluation against real held-out slices from `ai-engine/datasets/cicids2017/`.
4. **Comprehensive Unit Tests (`ai-engine/tests/test_model_evaluation.py`)**:
   - Added 9 new unit tests covering:
     - Hand-calculated confusion matrices (TN=1, FP=1, FN=1, TP=2, FPR=0.5, FNR=0.3333).
     - 100% false negative rate edge case (zero detections).
     - 100% perfect detection edge case.
     - Single-class BENIGN ground truth (zero positives, guarded zero-division).
     - Single-class Attack ground truth (zero negatives, guarded zero-division).
     - Empty inputs and length mismatches.
     - Real CICIDS held-out evaluation (`test_evaluate_cicids_held_out`).
   - **Result**: 15 of 15 tests passed in 24.02s.

### 2.3 Detection Quality & Autonomous Containment Verdict

> [!WARNING] **CRITICAL POLICY DIRECTIVE: AUTONOMOUS CONTAINMENT RESTRICTION**  
> While `rf_classifier_cicids_v2.pkl` achieves outstanding detection accuracy (>99%) on CICIDS2017 PCAP flows, its 100% false-negative rate on out-of-distribution synthetic traffic confirms that **the model is highly sensitive to distributional drift and flow feature alignment**.  
> **Autonomous host containment (automated Windows Firewall blocking without analyst confirmation) MUST NOT be enabled.** The system must remain configured in `MONITOR` or `HUMAN_IN_THE_LOOP` mode until calibrated against real enterprise endpoint traffic.

## 3. Priority 2 — Security Event Durability & Outbox Architecture

### 3.1 Audit of `SecurityEventBus.publishDurable()`

The audit inspected `SecurityEventBus.publishDurable(eventInput, persistFn, io)` to determine whether the event envelope itself was persisted or merely caller business state:

1. **Pre-Publish State Commitment**:
   - `publishDurable()` invokes `await persistFn(envelope)` before emitting to in-process subscribers or WebSockets. If `persistFn` fails (e.g. database error), the event is dropped, preventing phantom notifications for uncommitted state.
2. **Crash Recovery Reality**:
   - Prior to remediation, `SecurityEventBus` maintained only an in-memory ring buffer (`this.history = []`).
   - If the Node.js process crashed immediately after `publishDurable()` or during subscriber execution, the event envelope was lost. Upon restart, the bus initialized with an empty buffer and did not replay unacknowledged events.

### 3.2 Implemented Durable Outbox Pattern

To provide genuine crash-resilience without requiring breaking schema migrations on the live MongoDB database:

1. **`OutboxStore` Abstraction (`backend/utils/securityEventBus.js`)**:
   - Defined `OutboxStore` contract with `persistEnvelope()`, `markDelivered()`, `markFailed()`, and `getPendingEvents()`.
2. **`InMemoryOutboxStore` & `FileOutboxStore`**:
   - `InMemoryOutboxStore`: Used for fast in-process lifecycle tests and transient subscriber failure testing.
   - `FileOutboxStore`: Persists pending envelopes to an atomic JSON storage file (`backend/logs/event_outbox.json`), surviving process crashes and restarts.
3. **Outbox Recovery & Delivery Acknowledgment**:
   - `publishDurable()` persists the envelope to the outbox store with status `PENDING`.
   - `publish()` tracks subscriber handler errors; if any handler throws, status is marked `partial_delivery_error`.
   - `replayPendingOutbox()` replays pending events on backend startup and confirms delivery once all subscribers succeed.
4. **Automated Verification**:
   - Verified via `backend/tests/securityObservability.test.js`:
     - `recovers pending outbox events across simulated process restart`: PASSED.
     - `FileOutboxStore persists pending events to disk file`: PASSED.

## 4. Priority 3 — Windows Graceful Shutdown & WinSW Service Reality

### 4.1 WinSW Signal Delivery & Win32 Session 0 Analysis

WinSW is designed to wrap executables as Windows Services. However, signal delivery on native Windows differs fundamentally from POSIX systems:

1. **Absence of POSIX Signals**:
   - Windows has no native `SIGTERM` or `SIGINT`. Node.js on Windows emulates `SIGINT` only when connected to an interactive console receiving Win32 `CTRL_C_EVENT`.
2. **Session 0 Isolation**:
   - Windows Services run under `services.exe` in **Session 0** (non-interactive session), where processes have no console attached to `CONIN$`.
   - WinSW's stop sequence invokes `GenerateConsoleCtrlEvent(CTRL_C_EVENT, processGroup)`. In Session 0, this call frequently fails or is ignored by headless processes.
   - When `GenerateConsoleCtrlEvent` fails or `<stoptimeout>` expires, WinSW falls back to `Process.Kill()`, which calls the Win32 API `TerminateProcess()`. `TerminateProcess` immediately halts execution; Node.js cleanup hooks and `GracefulShutdownManager` are completely bypassed.
3. **Child Process Verification**:
   - An isolated test script (`scratch/test_graceful_child_process.js`) proved empirically that executing `child.kill('SIGINT')` from Node.js on Windows results in `read ECONNRESET` because Node.js translates `child.kill()` directly into `TerminateProcess`.
   - When tested using an IPC channel (`child.send('shutdown')`), the child process cleanly received the command, drained in-flight HTTP requests, closed the server, and exited with code 0 in **410ms**.

### 4.2 Status and Documentation Updates

1. **WinSW Template Marked NOT RUNTIME VERIFIED**:
   - Updated `docs/templates/winsw-sentinelai-backend.xml` with an explicit notice:
     `RUNTIME VERIFICATION STATUS: NOT RUNTIME VERIFIED ON HOST (SESSION 0 CONSTRAINT)`.
2. **IPC Shutdown Message Listener Added**:
   - Added `process.on('message')` in `backend/utils/gracefulShutdown.js` so that service supervisors or parent processes can coordinate graceful shutdown via IPC on Windows.
3. **Dedicated VM Validation Runbook**:
   - Provided a step-by-step procedure for deploying and testing WinSW in a dedicated Windows Server VM before production adoption.
